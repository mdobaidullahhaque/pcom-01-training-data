# pcom-01-training-data

Training dataset following the PCOM-01 record schema. Each row is one npm package version at a prediction date, labelled with the new GitHub Security Advisories (GHSAs) for that package in the next 90 days.

- **Prediction date (t0):** 2025-08-01T00:00:00.000Z
- **Features:** only data from before t0, with monthly series over the 12 full months before it
- **Targets:** new GHSAs published in [t0, t0 + 90 days), up to 2025-10-30, by severity
- **Size:** 1,912 rows, 225 columns (224 PCOM-01 core columns plus `prediction_date`), 26 positive rows (1.4%)

## Files

| File | Contents |
|---|---|
| `data/pcom01_training.sqlite`, `data/pcom01_training.csv` | The dataset, same data in both (table `pcom01_training`) |
| `data/packages_included.csv` | Included packages with stratum, source, purl, chosen version and `is_security_placeholder` |
| `data/packages.csv`, `data/packages_selection_stats.json` | All 3,771 selected packages and how they were selected |
| `data/initial_run_stats.json` | Time budget result, and the 19 skipped packages with reasons |
| `data/packages_test.csv` | 20 packages for pipeline tests only. Do not train on it: it was chosen to include positives |
| `data/allowed_blocked_files.json` | Ecosystems of 7 non-npm advisory files blocked by Windows Defender |
| `schema/schema.sql` | Schema, generated by `scripts/generate_schema.py` |
| `config.py`, `src/`, `tests/` | Settings, pipeline and tests |

## How to reproduce

Needs Python 3.10+. `GITHUB_TOKEN` must be set to a read-only token for the GitHub step; it is read only from the environment. Raw responses are cached in `data/cache/` (gitignored).

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

python -m src.advisory_snapshots --only latest t0 target_end
python -m src.advisories data\cache\advisory-db\latest
python -m src.advisories data\cache\advisory-db\t0
python -m src.advisories data\cache\advisory-db\target_end
python -u -m src.select_packages
python -u -m src.npm_meta
python -u -m src.github_activity
python -u -m src.run_initial
python -u -m src.build_dataset
python -m pytest
```

An exact rebuild is not guaranteed. The time budget depends on network speed and the cache, so a rerun can reach a different number of packages, and npm and GitHub data change over time. `data/packages_included.csv` records exactly which packages this version contains.

## Main decisions

- **Month index:** M0 = July 2025, the most recent full month before t0, and M11 = August 2024. Set by `M0_IS_MOST_RECENT` in `config.py`; not yet confirmed against the course sheet.
- **Version in `purl`:** highest stable semver version published before t0, else the highest version before t0. It must still have a manifest. Exact npm names are kept, including legacy uppercase ones.
- **Qualifying GHSA:** GitHub-reviewed, not withdrawn in that snapshot, and naming exactly this npm package.
- **Snapshots:** features and their severities use the advisory database as of t0 (`41c89aa`). Targets and their severities use it as of the end of the window (`abfbb63`). An advisory published before t0 but reviewed after it counts as neither.
- **Strata (seed 42), chosen using only pre-t0 information:**
  - A `had_ghsa`: all packages with a qualifying advisory before t0.
  - B `popular_no_ghsa`: from `npm-high-impact@1.11.0`, at least 1,000,000 downloads in the feature year.
  - C `random_no_ghsa`: from `all-the-package-names@2.0.2159`, 1,000 to under 1,000,000 downloads in the feature year.
- **CWE-506 (malware, account takeover):** kept as normal GHSAs. They are flagged by `is_cwe506` in the advisory cache table, which is not part of the 225 columns.
- **Security placeholders:** rows whose chosen version matches `0.0.x-security` are kept and flagged in `data/packages_included.csv`. Their GitHub columns are NULL, because they all share one repo.
- **Downloads:** days before a package existed are not counted as observed. A month with no observed days has NULL downloads.

## Limitations

- **Time budget:** this initial version covers 1,912 of the 3,771 selected packages (A 1,388, B 258, C 266). A 40-minute metadata budget left 1,840 unreached, and 19 reached packages were skipped. Packages were shuffled across strata first, so the reached ones are not biased by stratum.
- **GitHub issue and PR columns are mostly NULL (99.5% of cells):** only 9 rows have them, all from the pipeline test list, so they are not a random sample. The rest are to be added later.
- **Few positive rows:** 26 of 1,912 (1.4%), 25 of them from stratum A. Most packages that get a first-time advisory are not in the sample.
- **Group A is partly placeholders:** 152 of its rows are security placeholders, so their metadata describes npm's placeholder, not the original package.
- **Monorepos:** packages in one repo share that whole repo's activity, which is not specific to the package.
- **Survivorship:** packages fully unpublished after t0 are skipped, and those with unknown downloads could not enter strata B and C. Issues deleted or transferred after t0 are invisible.
- **`unpacked_size` and `file_count`:** NULL in 359 rows, mostly older versions. Tarballs were not downloaded to fill them.
- **Spam:** no quality filter was applied, so some packages may be spam.
- **Defender:** 7 non-npm advisory files could not be read on the build machine. GitHub's current data shows they are not npm.
